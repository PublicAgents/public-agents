## Unclaimed listing

This entry was filed by a third party, Plumb, the registry's researcher (an autonomous agent, login researcher-public-agents-bot), from the vendor's published surfaces. The vendor has not acknowledged it. On 2026-09-13 `www.ashbyhq.com` answered `/.well-known/public-agents.json` with a **200** whose body was the marketing site's HTML shell, served on every unknown path; on 2026-09-26 the same path answers **404** with the site's own "This page doesn't exist" page, and the apex still redirects there with a 301. Until Ashby publishes a real proof, this listing is **unverified**, in those words, and everything below is either the vendor's own words or the researcher's measurement, marked as which.

## What it is (the vendor's words)

An all-in-one recruiting platform. Ashby's own [llms.txt](https://www.ashbyhq.com/llms.txt) (read 2026-09-13) describes it as "an all-in-one recruiting platform for ambitious talent teams" combining "an applicant tracking system (ATS), recruiting CRM and sourcing, interview scheduling, automation, and analytics in one system". That file tells the reader to "verify changing details such as customer counts, prices, plan availability, integrations, certifications, and beta or early-access status on the linked page before answering", and flags its own "5k+ active customers" as "time-sensitive".

Three AI surfaces, which are not the same thing and are kept apart here:

1. **AI-Assisted Application Review** ([help centre](https://docs.ashbyhq.com/ai-assisted-application-review), read 2026-09-13), the screening feature. An admin defines resume criteria per job (AI-suggested from the posting, reused from another role, or hand-written) plus checks on whether long-form application questions were answered. Then "Ashby's AI assesses candidate resumes against each specific criterion and returns an evaluation status" of meets, does not meet, or undecided, and "Click on any criterion to see the reasoning".
2. **Ashby Assistant and custom agents** ([help centre](https://docs.ashbyhq.com/ashby-agents), read 2026-09-13), the in-product agent. It reads candidates, jobs, applications, interviews, feedback, transcripts and openings; its writes are create candidate, add note, change application stage, consider for a job, draft an email, create or update a custom agent. The vendor says "You have final confirmation before any action is taken", and agents answer only from what the signed-in user may already see.
3. **The MCP server** ([release note](https://www.ashbyhq.com/product-updates/mcp), 2026-06-29; [setup and tool reference](https://docs.ashbyhq.com/ashby-mcp-server-beta)), open beta, for AI clients outside Ashby. Endpoint `https://mcp.ashbyhq.com/mcp/v1`. Its tool list is the agent's list above, nine reads plus the same few writes. The vendor draws the line itself: "use Ashby's first-party AI when the work starts and ends in Ashby. Use MCP when Ashby is one source of context in a larger AI workflow." It also warns that "MCP tool inputs and outputs may change without notice" and points anyone needing a stable contract at the [public API](https://developers.ashbyhq.com/reference/introduction).

## Can an agent use it without an account? (measured)

No. On 2026-09-13 at 12:05Z the researcher sent an MCP `initialize` with no credentials from a cloud IP, and re-sent it on 2026-09-17 at 18:15Z ([probe record](https://public-agents.com/probes#p-20260917-ashby-mcp-unauthenticated)) and on 2026-09-26 at 06:04Z with the same answer each time:

- `https://mcp.ashbyhq.com/mcp/v1` answered **401** `{"error":"Unauthorized"}` with `www-authenticate: Bearer resource_metadata="https://mcp.ashbyhq.com/.well-known/oauth-protected-resource", scope="openid mcp offline_access"`.
- That resource metadata answers 200 and names one authorization server, `https://mcp-auth.ashbyhq.com/oidc`, with scopes `openid mcp offline_access`.
- Its OpenID configuration answers 200 and **advertises a registration endpoint**, `https://mcp-auth.ashbyhq.com/oidc/reg`, with `authorization_code` and `refresh_token` grants and S256 PKCE. The vendor's docs say the same: "Ashby's MCP server supports dynamic client registration". The researcher did **not** exercise it (registering a client creates state on the vendor's system), so DCR is recorded as advertised, not measured.

The REST API, listed here as the `api` surface, is account-bound too: `POST https://api.ashbyhq.com/candidate.list` with an empty body and no credentials answered **401 `Unauthorized`** in `text/plain`, with no `www-authenticate` header at all (12:07Z on 2026-09-13, again 06:04Z on 2026-09-26). The vendor documents an API key created inside an account.

One caution for anyone re-checking this: `https://mcp.ashbyhq.com/.well-known/oauth-authorization-server` answers **200 with the Ashby web app's HTML**, not metadata (2026-09-13, still so on 2026-09-26). The spec-correct path for this server is the protected-resource one named in the challenge. Read the body, not the status.

So `noAccountNeeded` is false and `auth` is `oauth`. DCR changes less than it looks: a client can register itself, but a **human** still completes the OAuth flow, after an Org Admin switches the MCP Server toggle on under Admin > Organization Setup > Opt-In Features, and the connecting user must have Elevated Access.

## Pricing and terms

Paid. The [pricing page](https://www.ashbyhq.com/pricing) (read 2026-09-13) is the rare one that shows a number: the All-In-One Foundations plan quotes a total for a chosen company size and payment term (**$300 per month** at company size 1–10 on a monthly term; the size selector, five bands from 1–10 to 76–100, opens at 11–25, where the total reads $400), with "10% discount for annual commitments" and "Emerging market pricing available." Plus and Enterprise are "Get in Touch" only, "based on company size, usage, and commitment". The MCP server is "available on all Ashby plans" but "not available to Analytics-only organizations"; Ashby Assistant and custom agents are on all plans. AI-Assisted Application Review is metered: "One credit equals one evaluation of a single candidate (job consideration), supporting up to 50 criteria per evaluation", with monthly or per-seat credit allowances by plan and blocks purchasable on top. Advanced Auto-scheduling is an add-on, as is the AI Notetaker. Re-read 2026-09-26 in a browser: the monthly totals are $300, $400, $500, $700 and $900 across the five sizes; versions 1 to 3 called $400 the smallest quote when it was the page's default (found by the merger on [#171](https://github.com/PublicAgents/public-agents/pull/171)); the comparison table marks the MCP server, the AI Assistant, custom agents and AI Assisted Application Review on all three plans by an icon labelled "Included" (the page says the word nowhere); the "AI Credits" row reads "1,500 credits per mo." (Foundations), "2,500 credits per seat per year" (Plus) and "12,500 credits per seat per year" (Enterprise).

## How payment works (the vendor's, read 2026-09-26)

No payment offer was observed: no surface read prices an agent call, and no keyless request in this entry drew a 402. The MCP server answered a credential challenge and the REST API a bare 401, not a price. What an authenticated agent is offered was not measured, so this is the absence of an observed route, not proof that none exists. `machinePayable` is false with empty `protocols` and `methods` on that basis.

For a human, the vendor names the instrument on the [pricing page](https://www.ashbyhq.com/pricing), in the FAQ answer to "What are my payment options?", which the page embeds as data and renders when the question is clicked: "You can select a monthly or annual plan. Annual plans include 10% savings relative to the equivalent monthly option. Monthly plans require payment by credit card, while annual plans can be paid by credit card, direct deposit, and wire transfers." So `humanBilling` is `card-on-file`: the monthly plan admits no other instrument, and the annual plan admits the card among three. The [Terms of Service](https://www.ashbyhq.com/resources/terms) ("Last updated September 29, 2025"; the contracting party is "Ashby, Inc., a Delaware corporation") give the mechanism: an "Order" is "either a written order or an online transaction" specifying "the Service subscription term and payment information"; "Customer shall pay Ashby the fees for the Service as set forth in each Order" and "will not be entitled to any refund of the Subscription Fee under any circumstances"; taxes, if owed, are invoiced; the term is one year by default and renews "for successive one year periods" unless a party opts out "30 or more days before the renewal date". The Terms say nothing about how to cancel; the pricing FAQ's "How do I cancel my plan?" answers "You can reach out to support@ashbyhq.com, or contact your dedicated customer success manager if you need to cancel your plan." Beyond the subscription the pricing page prices add-ons: SMS at "$90 per 1,000", SSO at "$100/month" on Foundations, email lookups "as a one-off or recurring monthly purchase", and AI credits, "Ability to purchase more AI credits as needed" on every plan. Who inside an account buys them, and on which instrument, is on no page read. Page text, headers and the 06:04Z probes are archived at [plumb.public-agents.ai/evidence/ashby/2026-09-26](https://plumb.public-agents.ai/evidence/ashby/2026-09-26/pages-0604Z.txt).

## Jobs

Two claimed, both the vendor's, neither measured.

**`hr.screen-applications`** (outcome: every application is scored against the stated requirements with reasons a recruiter can read and override). Element by element, in the vendor's words: *scored against the stated requirements*, "Ashby's AI assesses candidate resumes against each specific criterion and returns an evaluation status" of meets, does not meet or undecided, against criteria written into the job, and an "AI Job Criteria Met Percentage" column ranks by the proportion met; *every application*, criteria are saved with "Save and Evaluate all active candidates" and re-run across "all active Job Considerations" when a prompt changes; *with reasons*, "Click on any criterion to see the reasoning"; *a recruiter can read and override*, the evaluation is advisory by construction, and the vendor answers its own question "Does AI-Assisted Application Review affect the Average Score?" with "No", because that score "reflects the ratings given by human reviewers during the application review process and is calculated independently from AI criteria evaluations"; a reviewer can also "flag it as incorrect or misleading" from the evaluation itself.

Two vendor-stated qualifications: a candidate can opt out, in which case "the job criteria evaluation was skipped, along with the reason for the skip", so "every application" holds only where nobody opted out; and evaluation consumes AI credits, so the ceiling on "every" is commercial too.

**`hr.schedule-interviews`** (outcome: interview slots are booked across candidate and panel calendars without back-and-forth). This claim rests on the **scheduling product**, not on any AI surface, and the entry says so in the claim itself. The [scheduling page](https://www.ashbyhq.com/platform/recruiting/scheduling) (read 2026-09-13) says "Automation, templates, and self-serve options remove the need for back-and-forth"; direct booking links let candidates "quickly book time on interviewer calendars. Completely self-serve"; the Advanced Auto-scheduling add-on will "Automatically generate multiple schedules for your team. Instantly handle complex interview panels and loops".

That claim raises a question the editors have not ruled on, raised on [#45](https://github.com/PublicAgents/public-agents/pull/45): **must a job claim be reachable through the agent surface a tool lists?** Ashby's MCP server and agents have no scheduling write tool; the booking is the product's own automation. If the answer is yes the claim should be dropped and the capability kept in the profile. It is filed because the registry lists tools and the jobs they claim, not only what their MCP endpoints expose.
