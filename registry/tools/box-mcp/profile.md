## Unclaimed listing

Box has not claimed this entry. The registry's ownership file is absent from every host this listing names: `box.com/.well-known/public-agents.json` answers 404 (146 bytes of HTML), `developer.box.com` answers 404 with an empty body, and on `mcp.box.com` that path answers **401**, like every other path of that host except one. `_public-agents.box.com` has no TXT record (NXDOMAIN over DNS-over-HTTPS, 2026-10-20). So every claim below is either the vendor's own documented words or this researcher's measurement, and the entry stays unverified until Box publishes a proof naming it.

## What it is

The **Box MCP server** is, in the vendor's words on [its own guide](https://developer.box.com/guides/box-mcp/index), a "Hosted Model Context Protocol (MCP) server at https://mcp.box.com that lets AI agents search and use Box files over OAuth", and "It lets AI agents and apps search and use Box files over OAuth, without you handling raw file payloads in the client." The same page says "**Box hosts MCP** at `https://mcp.box.com`" and "You connect your client or agent platform to this URL; you do not run Box’s MCP server yourself for the standard integration", and carries a warning that "The **self-hosted** Box MCP server (open-source community project) is **deprecated**. Do not start new work on it."

## Agent access, as documented and as measured

The registry's one question is what a human must do before an agent can use the tool, and this vendor answers it in its own setup guide: **two human steps, not one.** An administrator enables the server in the Box Admin Console, and then, for a client Box does not already list, creates **Integration Credentials**: the guide's own sequence ends "Copy the generated **Client ID** and **Client Secret**", "Enter the **Redirect URI** provided by the external MCP client", "Select desired **Access Scopes**". The client side then needs the endpoint URL, the client id and secret, "an MCP name: `box-remote-mcp`", and "an `authorization_token`".

**A third gate sits inside the tool list.** The [Available tools](https://developer.box.com/guides/box-mcp/tools) page says it lists tools "including which tools an admin must turn on before agents can use them", and "Tools marked **Off** in the **Default** column need an admin to turn them on." Counted from that page's own tables on 2026-10-20: **53 tools, of which 37 are On by default and 16 are Off.** The 16 are `add_file_shared_link`, `add_folder_shared_link`, `create_collaboration`, `create_docgen_batch`, `get_download_url`, `get_upload_url`, `move_file`, `move_folder`, `set_file_metadata`, `set_folder_metadata`, `update_collaboration`, `update_file_properties`, `update_folder_properties`, `update_hub`, `update_metadata_template`, `upload_file_version`: every one of them writes, moves, shares or hands out a URL. An agent whose operator enabled the server still cannot upload, move or share until an administrator makes a second decision, and the registry's `agentAccess` has no cell for that shape.

The vendor is explicit that the server adds no authority: "Connecting any agent platform to Box does **not** bypass file permissions. Box checks collaborations, waterfall folder permissions, and application scopes on every request", and "The MCP server does not impersonate other users or search the enterprise unless the identity already can." Those are the vendor's claims, not measurements; nothing here tested them, because testing them needs an account and content.

**Measured 2026-10-20 between 18:33:58.945Z and 18:34:03.287Z, one container, one IP, no credential, no account, no payment, no cookie, nothing written** ([transcript](https://plumb.public-agents.ai/evidence/box-mcp/2026-10-20/keyless-and-docs-1833Z.txt), eleven requests and four documentation twins):

- `POST https://mcp.box.com` with an MCP `initialize`: **401, zero bytes**, and an RFC 9728 challenge: scheme Bearer, then the parameters `realm` (Service), `error` (invalid_request), `error_description` ("The access token was not found.") and `resource_metadata`, naming `https://mcp.box.com/.well-known/oauth-protected-resource`. The `/mcp` path form answers identically. Probe record `p-20261020-box-mcp-initialize-keyless`.
- That protected-resource document answers **200, 406 bytes**: `resource` `https://mcp.box.com/`, `resource_name` "Box Model Context Protocol Server", one authorization server, `https://api.box.com/`, `bearer_methods_supported` `["header"]`, and a `resource_documentation` URL plus a policy and a terms URL that are the same page.
- **Every other path of `mcp.box.com` that this prober touched answers 401 with an empty body**, including the path-aware protected-resource URI `/.well-known/oauth-protected-resource/mcp`, `/.well-known/oauth-authorization-server`, and `/.well-known/public-agents.json`. A host that refuses its own well-known paths with the resource server's own challenge is a shape worth naming: a reader cannot tell absence from refusal there, and the registry's ownership check on that host therefore establishes nothing either way.
- `GET https://api.box.com/.well-known/oauth-authorization-server`: **200, 798 bytes**. `issuer` `https://api.box.com`, authorization endpoint at `account.box.com/api/oauth2/authorize`, token and revocation endpoints at `api.box.com`, `response_types_supported` `["code"]`, `grant_types_supported` authorization_code and refresh_token, `token_endpoint_auth_methods_supported` client_secret_basic and client_secret_post, `code_challenge_methods_supported` **S256 only**. There is **no `registration_endpoint` and no `client_id_metadata_document_supported`**, so this server belongs to the "neither" class of the client-identification census in [issue #280](https://github.com/PublicAgents/public-agents/issues/280): an agent can neither register itself dynamically nor present a client-ID metadata document, which is exactly consistent with the documented flow where an administrator mints the credentials by hand. Probe record `p-20261020-box-mcp-authorization-server-keyless`.
- `account.box.com` serves that document **byte for byte identically** (SHA-256 equal, both 798 bytes, read in the same minute). Two earlier readings in this registry found resource hosts whose root metadata differs from the issuer's; this one does not, and the equality is recorded because the absence of divergence is as much a measurement as its presence.
- `GET https://api.box.com/2.0/users/me` with no Authorization header: **401, zero bytes**, with the same challenge minus the `resource_metadata` parameter. The REST path and the MCP path refuse a stranger the same way.

So `noAccountNeeded` is **false** and `auth` is `oauth`: not one surface of this tool answers a caller who has no account, and the vendor documents no keyless tier to look for.

## Jobs

**None claimed.** The tool list names capabilities (search, question answering over one or many files, structured extraction, Doc Gen) and the taxonomy's existing jobs are outcomes this entry cannot evidence from documentation alone: every Box AI tool's documented outcome is phrased as an action on the authenticated user's content, not as a result a third party could check.
