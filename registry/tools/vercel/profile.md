## Unclaimed listing

This is a third-party listing. Vercel has not published an ownership proof naming this registry's editor, so the registry's editors maintain it. Everything below is either the vendor's own words on the vendor's pages, cited, or a measurement the researcher ran and dated.

## What it is

The subject is [Vercel MCP](https://vercel.com/docs/agent-resources/vercel-mcp), which the vendor calls "Vercel's official MCP server. It's a remote MCP with OAuth that gives AI tools secure access to your Vercel projects", served at `https://mcp.vercel.com`. The vendor says it enables an assistant to "Search and navigate Vercel documentation", "Manage projects and deployments", "Analyze deployment logs", and "Query visitors, page views, and custom events".

The page says the tools split into "public tools (available without authentication) and authenticated tools (requiring Vercel authentication)". Its security guidance says "Connecting to Vercel MCP grants the AI system you're using the same access as your Vercel user account", warns about prompt injection, and recommends human confirmation for changes. Its Markdown rendering omits the HTML's clause "your use is subject to Vercel's AI Product Terms" (2026-10-11, appendix (W3)).

The server's OAuth protected-resource metadata (`/.well-known/oauth-protected-resource`) names the resource `Vercel MCP`, the authorization server `https://vercel.com`, and the scope `openid`.

## Purchases the server makes on a team's behalf (the vendor's, read 2026-09-22, re-read 2026-10-11)

**A correction first, the researcher's omission.** The 2026-09-21 head named six of the tools page's eleven groups and not Purchase; the changelog entry ["Vercel MCP now supports purchases"](https://vercel.com/changelog/vercel-mcp-now-supports-purchases) is dated **July 21, 2026**, before the read. The reviewer found it.

What the page says, in the vendor's words. On 2026-10-11 the tools reference is an index of groups, and the Purchase tools live on its [Billing and Purchases](https://vercel.com/docs/agent-resources/vercel-mcp/tools/billing) page, which opens: "You can purchase credits and domains, add supported add-ons, or upgrade a team to Pro." Withdrawn, on no vendor page read that day: the September sentences "make purchases on behalf of a team. Charges go to the team's payment method immediately and are non-refundable" and "are being rolled out gradually" (in the researcher's [2026-09-26 archive](https://plumb.public-agents.ai/evidence/vercel/2026-09-26/probes-1206Z.txt); the search is appendix (W5) of the record's artifact). Every purchase runs the same **quote-then-confirm** flow: `get_purchase_quote` "is read-only and nothing is charged", "Charges are immediate and non-refundable", and returns the cost where Vercel can quote one, the applicable spend limit, and an `idempotencyKey` that "is a signed token of the quoted terms"; the matching `buy_*` tool is then called with `confirm: true`, the same parameters and that key. Quotes "expire after 5 minutes". The vendor states four guarantees: the same key twice "does not create a second charge"; a confirmation whose parameters do not match the quote is rejected; if no payment method is on file "nothing is charged" and the response carries a `billingUrl` to add one; a successful confirmation returns a `billingUrl` and a `proofUrl`.

The four `buy_*` tools, and what each commits a team to. `buy_pro` "starts recurring Pro billing immediately at the standard Pro price", and because "Vercel's API doesn't return the Pro subscription price" the quote carries a link to the pricing page instead of a number. `buy_credits` buys prepaid credits for v0, AI Gateway or Vercel Agent, "in whole US dollars (1–1000)", with plan prerequisites the vendor names (Agent credits need Pro, v0 credits need a paid v0 plan, AI Gateway credits need neither). `buy_addon` buys units of `siem`: "Only `siem` is available today". `buy_domain` registers one domain: the quote returns a live `purchasePrice`, the confirm step "must echo that price back as `expectedPrice`", "the order is rejected if the live price no longer matches", the registration term is priced in the quote and required at confirm, and the "full registrant (`contact`) details" are supplied on every confirm (the September reason is gone from the page). `get_domain_order` reads the asynchronous order's status.

**One place the vendor disagrees with itself.** The Billing page says the SIEM add-on requires that "the team must be on the Flex plan"; the changelog announcing the same tool says it "requires an Enterprise plan". Recorded as the vendor's inconsistency, not resolved here: no account was held and neither claim was tested.

Nothing in this section was exercised. No OAuth flow was completed, no quote was requested, no `buy_*` tool was called and nothing was bought. Every sentence above is the vendor's claim about its own product; the only requests measured on this endpoint are the keyless ones in the access section, none of them a purchase tool.

The [pricing page](https://vercel.com/docs/pricing) prices by usage: "Pro teams get a monthly usage credit instead, then move to on-demand pricing", team seats at "$20 / month per additional paid seat", and unit tables. Read as Markdown, which is what this registry's gate and the agent strings measured on 2026-10-11 receive (Vercel's recognition rule is unpublished), the page lacks the build machine table a browser is shown and states the bulk-redirect and Global Config prices differently from the HTML (`p-20261011-vercel-docs-pricing-markdown-lacks-builds-table`, 2026-10-11). The MCP server carries no separate price on any page read; a tool call is billed as the underlying Vercel product.

The vendor is `Vercel Inc.`, from its [AI Product Terms](https://vercel.com/legal/ai-product-terms). Prices and terms are the vendor's, read 2026-09-21.

## How payment works

Nothing an agent can pay *for*. No surface read here prices an agent call and no request here drew a 402. The keyless documentation request answered 200 on 2026-09-25 and 401 Bearer on 2026-09-26; the account tools are gated by OAuth per the server. Neither is a price, so `machinePayable` is false with an empty protocol list.

The money this tool moves goes the other way, and that is why the enum stays false. The Purchase tools let an authenticated agent **spend**, against a card a human already put on the team, with no price ever quoted to the machine for the call itself. `machinePayable` records whether a machine can pay this tool for access, not whether this tool can spend a human's money on a machine's say-so; on that second question the vendor's documentation says yes. `methods` is empty for the same reason: no method here is one a machine presents.

For a human, the vendor is unusually direct, and the two paid tiers differ. The [Pro billing FAQ](https://vercel.com/docs/plans/pro-plan/billing) answers its own question "What payment methods are available?" with "Credit/Debit card only". Asked "Can I pay by invoice?", the same page answers "Yes. If you have a card on file, Vercel will charge it automatically", which is a receipt against a card rather than an invoice to remit. The [Enterprise billing FAQ](https://vercel.com/docs/plans/enterprise/billing) lists two methods, "Credit card" and "ACH/Wire", and says a card payment is taken "When the invoice is finalized in Stripe". So `humanBilling` is `card-on-file`, exactly true of the self-serve tier and the default of the other; ACH and wire exist only on Enterprise and are recorded here, not in the enum.
