## Unclaimed listing

This is a third-party listing. Vercel has not published an ownership proof naming this registry's editor, so the entry is maintained by the registry's editors and opens with this line. Everything below is either the vendor's own words on the vendor's pages, cited, or a measurement the researcher ran and dated.

## What it is

The subject is [Vercel MCP](https://vercel.com/docs/agent-resources/vercel-mcp), which the vendor calls "Vercel's official MCP server. It's a remote MCP with OAuth that gives AI tools secure access to your Vercel projects", served at `https://mcp.vercel.com`. The vendor says it "integrates with popular AI assistants like Claude" and enables an assistant to "Search and navigate Vercel documentation", "Manage projects and deployments", "Analyze deployment logs", and "Query visitors, page views, and custom events".

The page says the tools split into "public tools (available without authentication) and authenticated tools (requiring Vercel authentication)". Its security guidance says "Connecting to Vercel MCP grants the AI system you're using the same access as your Vercel user account", warns about prompt injection through untrusted tools, and recommends human confirmation for changes. Its Markdown front matter carried `last_updated: 2026-09-15` on 2026-09-25 (2026-08-13 when the entry was filed).

The server's OAuth protected-resource metadata (`/.well-known/oauth-protected-resource`) names the resource `Vercel MCP`, the authorization server `https://vercel.com`, and the scope `openid`.

The call is filed as `p-20260925-vercel-mcp-doc-tool-anonymous`. So the job this entry claims ran for a caller with no account, and `noAccountNeeded` is `true` at the level of the claimed jobs, the level the registry reads it at.

## Purchases the server makes on a team's behalf (the vendor's, read 2026-09-22)

**A correction first, because the omission was the researcher's and not the vendor's.** The 2026-09-21 head of this profile named six of the tools page's eleven groups and not the five that follow, of which one is Purchase. That was not drift: the changelog entry ["Vercel MCP now supports purchases"](https://vercel.com/changelog/vercel-mcp-now-supports-purchases) is dated **July 21, 2026** and the tools page's front matter carries `last_updated: 2026-09-15`, both before the read, and the Wayback Machine holds no snapshot of the tools URL (checked 2026-09-22). The section was there and was missed; the registry's reviewer found it.

What the page says, in the vendor's words. The Purchase tools "make purchases on behalf of a team. Charges go to the team's payment method immediately and are non-refundable", and they "are being rolled out gradually and may not yet be available on your connection". Every purchase runs the same **quote-then-confirm** flow: `get_purchase_quote` is "read-only and nothing is charged", and returns the cost where Vercel can quote one, the applicable spend limit, and an `idempotencyKey` that "is a signed token of the quoted terms"; the matching `buy_*` tool is then called with `confirm: true`, the same parameters and that key. Quotes "expire after 5 minutes". The vendor states four guarantees: the same key twice "does not create a second charge"; a confirmation whose parameters do not match the quote is rejected; if no payment method is on file "nothing is charged" and the response carries a `billingUrl` to add one; a successful confirmation returns a `billingUrl` and a `proofUrl`.

The four `buy_*` tools, and what each commits a team to. `buy_pro` "starts recurring Pro billing immediately at the standard Pro price", and because "Vercel's API doesn't return the Pro subscription price" the quote carries a link to the pricing page instead of a number. `buy_credits` buys prepaid credits for v0, AI Gateway or Vercel Agent, "in whole US dollars (1 to 1000)", with plan prerequisites the vendor names (Agent credits need Pro, v0 credits need a paid v0 plan, AI Gateway credits need neither). `buy_addon` buys units of `siem`, "the only" add-on. `buy_domain` registers one domain: the quote returns a live `purchasePrice`, the confirm step "must echo that price back as `expectedPrice`", "the order is rejected if the live price no longer matches", the registration term is priced in the quote and required at confirm, and the full WHOIS `contact` is supplied on every confirm because "Vercel stores no reusable registrant profile". `get_domain_order` reads the asynchronous order's status.

**One place the vendor disagrees with itself.** The tools page says the SIEM add-on requires that "the team must be on the Flex plan"; the changelog announcing the same tool says it "requires an Enterprise plan". Recorded as the vendor's inconsistency, not resolved here: no account was held and neither claim was tested.

Nothing in this section was exercised. No OAuth flow was completed, no quote was requested, no `buy_*` tool was called and nothing was bought. Every sentence above is the vendor's claim about its own product; the only requests measured on this endpoint are the keyless ones in the access section, none of them a purchase tool.

## Pricing and terms

Freemium. The plans page names three: Hobby, free, "designed for personal projects and developers"; Pro, which "introduces a flexible credit-based system that provides transparent, usage-based billing"; and Enterprise. The [pricing page](https://vercel.com/docs/pricing) prices the platform by usage: "Pro teams get a monthly usage credit instead, then move to on-demand pricing", team seats at "$20 / month per additional paid seat", and a unit table (build minutes at $0.0035 per CPU minute, and more). The MCP server carries no separate price on any page read; what a tool call does is billed as the underlying Vercel product is billed.

The vendor is `Vercel Inc.`, from its [AI Product Terms](https://vercel.com/legal/ai-product-terms). Prices and terms are the vendor's on 2026-09-21 and change without notice.

## How payment works

Nothing an agent can pay *for*. No surface read here prices an agent call and no request in this entry drew a 402: the server's account tools are gated by OAuth and its public tools by nothing, neither by a price, so `machinePayable` is false with an empty protocol list.

The money this tool moves goes the other way, and that distinction is why the enum stays false. The Purchase tools let an authenticated agent **spend**, against a card a human already put on the team, with no price ever quoted to the machine for the call itself. `machinePayable` records whether a machine can pay this tool for access, not whether this tool can spend a human's money on a machine's say-so; on that second question the vendor's documentation says yes. `methods` is empty for the same reason: no method here is one a machine presents. Read the other way, as the methods a purchase moves over, `card` belongs in it; the field is one line to change.

For a human, the vendor is unusually direct, and the two paid tiers differ. The [Pro billing FAQ](https://vercel.com/docs/plans/pro-plan/billing) answers its own question "What payment methods are available?" with "Credit/Debit card only", and names what is not accepted: "gift cards, prepaid cards, EBT cards, and some virtual cards". Asked "Can I pay by invoice?", the same page answers "Yes. If you have a card on file, Vercel will charge it automatically", which is a receipt against a card rather than an invoice to remit. The [Enterprise billing FAQ](https://vercel.com/docs/plans/enterprise/billing) lists two methods, "Credit card" and "ACH/Wire", and says a card payment is taken "When the invoice is finalized in Stripe". So `humanBilling` is `card-on-file`, which is exactly true of the self-serve tier and the default of the other; the ACH and wire path exists only on Enterprise and is recorded here rather than in the enum.

## Jobs

Two claimed as the vendor's claim; the first is now also measured once, the second is not.

`eng.retrieve-reference-context`, on the [Vercel MCP page](https://vercel.com/docs/agent-resources/vercel-mcp): the server lets an assistant "Search and navigate Vercel documentation". The job's outcome is a coding agent working from current, version-correct reference material for what it touches; the vendor's words cover retrieval of Vercel's own documentation into an assistant's context, and the scope is Vercel's documentation only. Measured 2026-09-25: a keyless `tools/call` of `search_vercel_documentation` returned documentation sections with source URLs (`p-20260925-vercel-mcp-doc-tool-anonymous`); the same call answered 401 on 2026-09-21. One topic, one request: whether the search is current or complete for a given topic is not measured.

`proc.purchase-on-behalf`, on the [tools reference](https://vercel.com/docs/agent-resources/vercel-mcp/tools): the Purchase tools "make purchases on behalf of a team" and reach a completed, charged order (`buy_credits` and `buy_pro` charge on confirmation; `buy_domain` returns an `orderId` whose status `get_domain_order` reads). The job's definition claims it for a vendor that "says the agent path reaches checkout completion or a confirmed-order handoff" and records prerequisites (an account, a token, a granted purchase permission) in `agentAccess` and the profile rather than as a reason to withhold the claim, so the OAuth gate and the vendor's "team role with billing access" sit there. It is the vendor's claim and nothing was bought: the catalogue being purchased from is Vercel's own product list, not a third-party one.

Not claimed: managing projects and deployments, analysing deployment logs, querying Web Analytics, the Access, Design import, Toolbar, CLI, Domain and Agent Runs Observability tool groups have no job in the current taxonomy whose whole outcome the vendor's words cover, so no claim is filed for them; the profile records the capability and the empty cell.
