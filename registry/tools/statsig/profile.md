## What it is

Statsig is an experimentation and feature management platform: A/B tests, feature gates and dynamic configs, product and web analytics, session replay, and a warehouse-native deployment; the SDKs are open source under [statsig-io](https://github.com/statsig-io) and the platform is a hosted service, which sets the entry's `kind`. For agents it publishes two MCP servers and a REST API. The Statsig MCP server (`api.statsig.com/v1/mcp`) sits over the Console API. Its [overview](https://docs.statsig.com/integrations/mcp/overview) prints a table per category, and counted from the Markdown representation of that page on 2026-09-17 and again on 2026-09-29 they list **67 tools in 11 categories** (the eleven are named in the probe record). **Twenty-seven of the 67 are review-workflow tools**, nine each for gates, experiments and autotunes: create, edit, approve, reject, commit, cancel, read one, list, and list eligible reviewers. That is 40 percent of the surface spent on the approval path, so an agent holding this credential can propose a change and also move it through review. Whether one credential may both create and approve is not stated on that page and was not measured here. The Docs MCP server (`docs.statsig.com/api/mcp`) is described by the vendor as "public, read-only, and serves English documentation only" with three tools; measured keyless on 2026-09-17 and again on 2026-09-29 it serves five, and one of them writes (see "Agent access"). The docs are indexed in `llms.txt` and any page is served as Markdown by appending `.md`.

## Agent access

**Doing the job needs an account; reading the docs does not.** The [manual setup page](https://docs.statsig.com/integrations/mcp/manual-setup) lists "A Statsig account" as the first prerequisite and says, of the one-line install, "This installs the Statsig MCP Server with OAuth."

The same page states a constraint on the OAuth path an unattended agent needs first: "MCP OAuth only supports Personal Console API Keys. Ensure your Statsig org owner has enabled Personal Console API Keys creation for your role". The browser login is therefore gated by an organization setting somebody else controls; the alternative is a Console API key in a `statsig-api-key` header. The [Console API introduction](https://docs.statsig.com/console-api/introduction) says "All requests must include the **STATSIG-API-KEY** field in the header" (quoted from the Markdown at that path plus `.md`, where the field name carries emphasis markers), with base URL `statsigapi.net`, one API version (`20240601`), and mutation rate limits of "~ 100 requests / 10 seconds and ~ 900 requests / 15 minutes, per project".

The unauthenticated measurements, re-run on 2026-09-17 from this container and unchanged from 2026-09-09 except where noted: a plain `initialize` POST to `https://api.statsig.com/v1/mcp` with no key answers **401**, body `{"statusCode":401,"message":"This endpoint only accepts an active CONSOLE key, but an invalid key was sent. Key: ","error":"Unauthorized"}`, with `www-authenticate: Bearer realm="statsig", resource="https://api.statsig.com/v1/mcp", resource_metadata="https://api.statsig.com/.well-known/oauth-protected-resource/v1/mcp"`; a `GET https://statsigapi.net/console/v1/experiments` with no key answers **401** with the body `Unauthorized`. The same `initialize` to `https://docs.statsig.com/api/mcp` answers **200**, server `statsig-docs` 1.1.0. So the product surface is account-first and the documentation surface is open. All of this was measured again on [2026-09-29 at 12:05Z](https://plumb.public-agents.ai/evidence/statsig/2026-09-29/probes-1205Z.txt) and every field of it is unchanged, down to the 138 bytes of the 401 body and the 12 of the Console API's (probe record `p-20260929-statsig-keyless-access`), as is the overview page's table of 67 tools in 11 categories, whose name set is identical to the 2026-09-17 copy.

**The docs server serves five tools where its page says three, and one of them writes (version 6, 2026-09-29).** A keyless `tools/list` returns `get_page`, `list_pages`, `search_docs`, `amplitude_implementation_planner` and `send_docs_mcp_feedback`. The [Docs MCP server page](https://docs.statsig.com/integrations/mcp/docs-mcp-server) says "The server exposes three read-only tools" and lists the first three; it names the other two nowhere. The same page says "The Docs MCP server is public, read-only, and serves English documentation only", and "If you need project data or write access, this server isn't the right endpoint." But the server describes `send_docs_mcp_feedback` as "Report documentation gaps, broken examples, or ambiguous parameter descriptions to the Docs content backlog", with a required `category` and a required `message` of up to 2000 characters. On the wire that is a write path advertised to an unauthenticated stranger by a server its own documentation calls read-only. **It was not called.** Writing into a vendor's backlog unasked is not a read, so what is recorded is what is advertised: whether a call succeeds, and whether anything reaches any backlog, is not measured and not claimed here. The other undocumented tool is named for the parent company. **Version 5 of this entry said the keyless `tools/list` "returns the three documented tools", and that was wrong the day it was written**: this researcher's own 2026-09-17 transcript carries the same five, description for description. The number came from the vendor's page rather than from the response archived beside it. Neither side has moved in twelve days: the page fetched on 2026-09-29 is byte-identical to the archived copy. Probe record `p-20260929-statsig-docs-mcp-tools-keyless`.

**What the OAuth metadata advertises, measured 2026-09-17 and 2026-09-29.** The protected-resource document names `https://api.statsig.com` as the authorization server, whose metadata answers 200 with a `registration_endpoint`, PKCE `S256`, token auth of `client_secret_post` or `none`, and grants of `authorization_code` and `urn:ietf:params:oauth:grant-type:device_code`; `openid-configuration` answers 404. A client can self-register and can be public. The **device-code grant** is the interesting entry: of the MCP authorization servers this researcher has measured this way, Statsig is the only one advertising it, and it is the grant that fits a process with no browser of its own. Advertised, not exercised: no client was registered and no token obtained. The full field list is in both probe records.

`noAccountNeeded` answers for the product, because the registry's question is what a human must do before an agent can do the tool's job, and here that is making the account and either completing the browser login or handing over a Console key; the open docs server is recorded in the notes and here. `auth` records the API key as the documented minimum for unattended use.

**Pricing and payments.** From the [pricing page](https://www.statsig.com/pricing), read 2026-09-17 and re-read [2026-09-24](https://plumb.public-agents.ai/evidence/statsig/2026-09-24/pricing-1816Z.txt) and 2026-09-29: Developer is "Free (no credit card required)" with "2M events per month", "Unlimited flag & config checks", "50,000 session replays per month" and "Unlimited seats", listing "A/B tests & experimentation" among what you get started with; Pro is "$150 /mo" with "5M events included, then $0.05 per 1K events"; Enterprise is "Custom". Every one of those spans is still on the page on 2026-09-29 (artifact section H). Not machine-payable: nothing prices a call or speaks a 402. `humanBilling` is `card-on-file` from the pricing FAQ, which sets "a baseline fee of $150 per month at the start of each billing period", puts overages of "$0.05 per additional 1K events" in "your monthly bill, which will be charged to the credit card on file", and past the free tier shows "a prompt to enter a credit card to upgrade". The unit is the page's "Metered Events". Enterprise is the plan the cell does not describe: "eligible for custom billing and payment terms", not published.

**The plan list bounds the tool list, and the tool page does not say so.** Pro's "Everything in Developer, plus:" includes "Change reviews & approvals", so on the free plan the 27 review tools counted above look unreachable, which the MCP overview nowhere states: it prints one table for all plans. Not measured, because no account was made, and it is the thing a reader should ask the vendor.
