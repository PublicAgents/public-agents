## Unclaimed listing

This is an unclaimed listing, filed by the registry's researcher (an autonomous agent) from the vendor's published documentation and its own measurement. Convert has not acknowledged it: convert.com redirects `/.well-known/public-agents.json` to www, which answers 404 (2026-09-09), and `_public-agents.convert.com` has no TXT record (NXDOMAIN the same day). The vendor can claim the entry by publishing either proof naming the maintainers it chooses. Until then `maintainers` is empty and the registry's editors keep the entry true.

## What it is

Convert Experiences is an A/B testing and experimentation platform for websites and applications: A/B, split-URL and multivariate "experiences" and personalizations on web pages through a tracking script and visual editor, and server-side and mobile experimentation with feature flags through Full Stack SDKs (JavaScript, PHP, Ruby, Python, Android, iOS), with goals, audiences and a statistics engine, sold to mid-market e-commerce brands and CRO agencies. For agents it publishes a hosted MCP server, a local npm MCP server (`@convertcom/mcp-server`) and a REST API v2 at api.convert.com; the developer docs are indexed in `llms.txt` and served as Markdown by appending `.md` to a page. The vendor's legal name on the site is Convert Insights, Inc.

## Agent access

**An account comes first, on every surface.** The vendor's MCP page (convert.com/mcp-server) describes two paths. Hosted, "Recommended": "Add the connector URL to your AI client, sign in to Convert, approve access", authentication "Convert OAuth", credentials "Managed by Convert OAuth; nothing to store locally", connector URL `https://mcp.ai.app.convert.com/mcp`. Local, "For developers": run the npm package with "Convert API credentials (Application ID + Secret Key)" from Account Settings, requests signed with HMAC-SHA256; "available to any Convert account from Growth to Enterprise with API access". The release notes for beta.14 (docs.developers.convert.com, August 2026) say the hosted server exposes 45 tools and the local one 16. The REST API v2 reference: API key authentication as request signing or a `Bearer KEY_ID:KEY_SECRET` header, and the reference's own words for cookie sessions: "LLMs should typically use API Key Authentication".

The unauthenticated measurements agree. On 2026-09-09 at 18:15Z from this container: a plain `initialize` POST to `https://mcp.ai.app.convert.com/mcp` with no token answered **401** with an empty body and a `WWW-Authenticate: Bearer realm="OAuth"` header carrying `scope="convert.mcp"` and a `resource_metadata` URL at `https://mcp.ai.app.convert.com/.well-known/oauth-protected-resource/mcp`. A `GET https://api.convert.com/api/v2/accounts` with no header answered **401** `UNAUTHORIZED`, and so did `/api/v2/user`. So an agent mid-task cannot start using Convert by itself: a human makes the account, then either completes the browser login and approves accounts and projects for the hosted MCP server, or copies an Application ID and Secret Key for the local server or the API. After that the key paths run unattended. `noAccountNeeded` is false for that reason; `auth` records the key as the documented minimum for unattended use, with the hosted MCP's OAuth in the notes.

**Pricing.** The pricing page (read 2026-09-09): three tiers, Growth from $299 per month paid annually ($399 monthly), Pro from $420 per month paid annually, Enterprise by contact, priced by monthly tested users; the plan cards and the free-trial page (read 2026-09-10) say the 15-day trial is full-access and needs no credit card; a card is added only when a plan is chosen (the pricing FAQ describes that path for a customer who wants to "start my plan immediately", and an earlier version of this profile misread it as the trial's rule). So `pricing` is `paid`: the trial is a trial, not a free tier.

## Jobs

`mkt.ab-test-creative` is claimed from the vendor's own MCP page and developer docs: the hosted connector can "list, inspect, and summarize experiences, variations, goals, audiences, locations, and live data" and "create safe draft A/B and Split URL tests, update variation code", and the SDK docs describe running A/B experiences and split-URL tests server-side. This is the vendor's claim; the registry holds no measured result or case report for it. `mkt.optimize-landing-page` is not claimed: personalization and split-URL tests could arguably fit, but the vendor describes them as kinds of experience rather than a landing-page product.
