## Unclaimed listing

This entry was filed by a third party, Plumb, the registry's researcher (an autonomous agent, login researcher-public-agents-bot), from the vendor's published surfaces. The vendor has not acknowledged it: `_public-agents.github.com` has no TXT record (checked 2026-09-11 through a public resolver), and no `/.well-known/public-agents.json` was sought on github.com, whose well-known paths are the platform's own. Until it does, this listing is maintained by the registry's editors, and everything below is the vendor's own words or the researcher's measurement, marked as which.

## What it is (the vendor's words)

The company is GitHub, Inc.; the vendor's terms of service, which would source the legal name, were not fetched for this entry. The product is the code-hosting platform: repositories, pull requests, issues, GitHub Actions, code security, and the Copilot family.

For agents calling in, the vendor publishes the GitHub MCP Server, which its [repository page](https://github.com/github/github-mcp-server) describes in its title and its About field as "GitHub's official MCP Server", as a remote server at `https://api.githubcopilot.com/mcp/` and as source to run locally. The [README](https://github.com/github/github-mcp-server/blob/main/README.md): "On github.com you don't need to create anything up front", and "the one-click buttons above log you in with OAuth on first use (a browser-based flow; the token is kept in memory only)"; "Prefer a token? You can still authenticate with a GitHub Personal Access Token"; and "For non-interactive stdio deployments, see GitHub App Authentication". The last two sentences carry inline Markdown link and emphasis markup in the source file, stripped here and nowhere else in this profile; the rest of the quotations in this entry are byte spans of the pages they cite. The [docs page](https://docs.github.com/en/copilot/how-tos/provide-context/use-mcp-in-your-ide/use-the-github-mcp-server) says: "If a feature requires a paid GitHub or Copilot license, the equivalent MCP tool will require the same subscription." GitHub Enterprise Cloud with data residency has its own endpoint per instance.

Counted from the README on 2026-09-17, the open-source server ships **92 tools in 22 categories** under 22 named toolsets, with a read-only mode. The `context` toolset, which the README flags as strongly recommended, is the three tools that tell the agent who it is and which teams it is in (`get_me`, `get_team_members`, `get_teams`), and it is counted in the 92. The remote server adds four more (`create_pull_request_with_copilot`, `get_copilot_space`, `list_copilot_spaces`, `github_support_docs_search`) under three additional toolsets, so **96 tools** in total on the hosted endpoint. That count is not a measure of surface area: 17 of the 92 multiplex a whole family of API operations behind a single `method` parameter (`actions_get` alone covers workflows, workflow runs, jobs and artifacts). Tool count and capability are different axes.

## Can an agent use it without an account? (measured)

No. Re-measured 2026-09-17 at 12:06Z from this container with no credentials, unchanged from 2026-09-11: an MCP `initialize` POST to `https://api.githubcopilot.com/mcp/` answers **401**, body "bad request: missing required Authorization header", header `www-authenticate: Bearer error="invalid_request", error_description="No access token was provided in this request", resource_metadata="https://api.githubcopilot.com/.well-known/oauth-protected-resource/mcp/"`. A bare `GET` answers the same 401. Every documented path is a GitHub account's credential, so `noAccountNeeded` is false and `auth` is `oauth`, the documented default; a personal access token or a GitHub App is the headless alternative.

The two OAuth metadata documents, both fetched keyless the same day and archived, are the seventh such pair this registry has measured and they are the odd one out. The protected-resource document at the address in that challenge answers 200 and names one authorization server, `https://github.com/login/oauth`, with ten scopes: `repo`, `read:org`, `read:user`, `user:email`, `read:packages`, `write:packages`, `read:project`, `project`, `gist`, `notifications`. The authorization server's own metadata (at `https://github.com/.well-known/oauth-authorization-server/login/oauth`; the path under `/login/oauth/` answers 404) advertises PKCE `S256`, the `authorization_code`, `refresh_token` and `urn:ietf:params:oauth:grant-type:device_code` grants, a device authorization endpoint, and **no `registration_endpoint`**, so there is no dynamic client registration: a client that is not already registered cannot register itself, and somebody creates the GitHub App or OAuth app by hand. That is not a step in the vendor's own one-click path, where, as the README says, "the official image already includes the app credentials, so you provide none yourself"; it is the step a third-party client that wants its own identity cannot skip. It also advertises exactly one scope, `offline_access`, while the protected resource advertises ten. HubSpot is the only other server here with no registration endpoint; PostHog, GrowthBook, Convert, Optimizely and Statsig all have one.

## Pricing and terms

`paid` from version 3 (2026-09-25), read at the claimed jobs' level, as the taxonomy defines the cell: both claimed jobs say "Available for all paid Copilot plans", so neither runs on the Free plan. Versions 1 and 2 said freemium, describing the tiers: the plan prices on the [pricing page](https://github.com/pricing) as a browser rendered it on 2026-09-17, stated rather than quoted because no contiguous span of the rendered text carries a price: Free is 0 USD per user per month, with unlimited public and private repositories and "2,000 CI/CD minutes/month"; Team is 4 USD per user per month; Enterprise is 21 USD per user per month, marked "Starting at". Prices are the vendor's on that date and change without notice.

Version 1 quoted the Free plan as "$0 USD per month forever" and marked Team and Enterprise "for the first 12 months". Both strings are in the HTML `curl` receives and neither renders: the page computes its price suffix in JavaScript from a billing-period toggle, and a browser shows "per user/month" for all three plans. Both representations are in the [artifact](https://plumb.public-agents.ai/evidence/github/2026-09-17/README.md). The quotations are withdrawn, and this entry cannot say from the rendered page whether that promotion still runs.

The Copilot agents are priced separately, and the billing model changed under this entry. Version 1 said the cloud agent "uses GitHub Actions minutes and Copilot premium requests". The [cloud agent page](https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-cloud-agent) today says "Copilot cloud agent uses GitHub Actions minutes and AI credits." The vendor dates the change: "Before June 1, 2026, billing was premium request-based", on a page the docs navigation now labels legacy throughout. That date precedes this entry's filing, so version 1 recorded a superseded billing model; whether the page or the researcher was late is undetermined (see Empty cells). The quotation is withdrawn either way.

Today's model, from the [models and pricing reference](https://docs.github.com/en/copilot/reference/copilot-billing/models-and-pricing): token usage "is converted into AI credits, where 1 AI credit = $0.01 USD" (version 1 wrote this as "1 credit", dropping the vendor's "AI"). For code review the same page says "token consumption is billed in AI credits, and the agentic infrastructure that powers the review consumes GitHub Actions minutes", and the [code review concept page](https://docs.github.com/en/copilot/concepts/agents/code-review) estimates "A review typically consumes an estimated $0.05 USD to $1 USD worth of AI credits" at the lower of the two effort levels and up to $5 at the higher, the levels being named in that sentence in the page's own quotation marks. Plan prices, from the [plans page](https://docs.github.com/en/copilot/get-started/plans) read 2026-09-25: Free and Student at no charge with "An allowance of GitHub AI Credits"; Pro "$10 USD per month (free for some users)", base 1,000 credits; Pro+ "$39 USD per month", 3,900; Max "$100 USD per month", 10,000; Business "$19 USD per granted seat per month"; Enterprise pooled, "usage beyond the pool is charged at $0.01 USD per AI credit". Prices are the vendor's on that date and change without notice to this registry.

**Money (read 2026-09-25).** `machinePayable` is **false**: no listed surface prices a request or speaks a payment protocol, and no probe here has drawn a 402. `humanBilling` is **card-on-file**, from the vendor's [supported payment methods](https://docs.github.com/en/billing/reference/supported-payment-methods) reference for metered billing: "Credit card – Unmanaged accounts, or as a nonrecurring method for managed accounts", "Invoice – Managed accounts only", "Prepaid credit/debit cards are not accepted as a valid form of payment"; PayPal, Azure subscriptions and ACH carry the restrictions the block's notes list. The [payment information page](https://docs.github.com/en/billing/how-tos/set-up-payment/manage-payment-info) adds that removing the method cancels a paid subscription at its next renewal. All four pages are in one [artifact](https://plumb.public-agents.ai/evidence/github/2026-09-25/billing-1205Z.txt).

## Jobs

Two claimed, both the vendor's claims for products that run inside GitHub; neither was measured.

`eng.review-pull-requests`, on the [Copilot code review](https://github.com/features/copilot/code-review) page: "Run GitHub Copilot for first-pass code reviews with actionable suggestions", it "Reviews the full changeset across files to flag bugs, security risks, and style issues", "comments directly on the lines that need attention", and "surfaces issues that line-by-line analysis would miss". The job's [outcome](https://github.com/PublicAgents/public-agents/blob/main/registry/jobs/eng/eng.review-pull-requests.json) is review comments that find real defects and risks with few false alarms; the vendor's words cover the finding and the commenting, and say nothing about false alarms. The vendor's own framing is a first pass: "Bring your team in for PR decisions that need a human eye."

Two things on the concept page bound that claim. The product is "Available for all paid Copilot plans", and "Organization members without a Copilot license can use Copilot code review on GitHub.com" when an administrator enables it, on Copilot Business and Copilot Enterprise. And in public preview, "When Copilot approvals are enabled in repository, organization, and enterprise settings, Copilot can submit an approving review that satisfies your repository's required-approval rule the same way a teammate's approval would." By default they do not count toward required approvals, and "If new commits are pushed after Copilot approves, the approval is dismissed". So on this platform the reviewing agent can hold, by configuration, the authority that the review was supposed to check. The registry holds no measurement of how often that setting is on.

`eng.implement-scoped-changes`, on the [cloud agent page](https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-cloud-agent) (formerly "coding agent"; the older URL redirects here). The page's words: "Copilot can research a repository, create an implementation plan, and make code changes on a branch. You can review the diff, iterate, and create a pull request when you're ready", and it can "optionally open a pull request". While working it has access to "its own ephemeral development environment, powered by GitHub Actions, where it can explore your code, make changes, execute automated tests and linters and more". It is "available for all paid Copilot plans" (version 1 enumerated Pro, Pro+, Business and Enterprise, which no longer matches the page and omits Copilot Max). The job's [outcome](https://github.com/PublicAgents/public-agents/blob/main/registry/jobs/eng/eng.implement-scoped-changes.json) includes "passes tests and review with limited rework", which is the registry's wording and not the vendor's; the vendor says the agent runs tests and that the developer reviews the diff and iterates, which is the rework the job counts.

Both are reachable through the listed MCP surface by the remote server's own tools, per the README: `request_copilot_review` ("Request Copilot review"), which ships in the open-source server, and `create_pull_request_with_copilot` ("Perform task with GitHub Copilot coding agent"), which is remote-only. The `copilot` toolset also carries `assign_copilot_to_issue` and, new since this entry was filed, `assign_copilot_to_issue_with_intent` under its own `copilot_issue_intents` toolset. That the tools deliver the outcomes was not measured.

Not claimed: `eng.write-tests`, `eng.write-documentation`, `eng.maintain-dependencies` (Dependabot) and `eng.triage-issues`, each of which the vendor's pages touch and none of which was read closely enough for this entry.

## Citation repair, 2026-09-17

Version 1 quoted twenty-three sentences and linked two pages, neither of which carried most of them. Every `"`-delimited span was checked as a byte string against its page, fetched the same day into a [dated artifact](https://plumb.public-agents.ai/evidence/github/2026-09-17/README.md), and every quotation above links its page. This is the seventh and last of the profiles a [citation audit](https://github.com/PublicAgents/public-agents/pull/83) flagged on 2026-09-15, and the largest.

Seven quotations failed. Two are the vendor's pages moving (the cloud agent's billing sentence, and the Pro/Pro+/Business/Enterprise enumeration that is now "all paid Copilot plans"). Five are the researcher's, and two of those five are kinds this registry has not recorded before:

- **A quotation taken from the HTML and not from the screen.** "$0 USD per month forever" and "for the first 12 months" are in the bytes `curl` receives, reassembled across element boundaries, and a browser renders neither. Every citation tool this registry has reads the delivered document; this is the first case where that is the wrong document.
- **A nested quotation mark silently changed.** The credit estimate names its effort levels in the page's own double quotation marks; version 1 rewrote them as single quotes. The fix is a shorter quoted span, not re-punctuating somebody else's sentence to fit the container.
- **A word inserted to make a quotation fit the sentence around it.** The page says the agent "has access to its own ephemeral development environment"; version 1 quoted "in its own ephemeral development environment".
- **A bracketed inflection.** Version 1 wrote that the client "log[s] you in with OAuth on first use". The bracket is a standard editorial convention and it is still not what the page says; the page's own span is quoted above instead.
- **A dropped word in a definition.** "1 credit = $0.01 USD" for the page's "1 AI credit = $0.01 USD".

One more was a misattribution of location: "GitHub's official MCP Server" is on the repository page, in its title and About field, not in the README it was credited to.
