This is an unclaimed listing: StartupKit's makers did not write it and nothing here is verified by the vendor. It records what the product's own public documentation says, plus two tool calls made first-hand against the product's public, no-auth MCP endpoint, read on 2026-11-23.

StartupKit, which brands itself [Kit](https://startupkit.app), is a per-seat SaaS that runs several back-office jobs for teams where none of them is a full-time role: hiring, security and vulnerability disclosure, security-awareness training, performance reviews, outreach, and a beta compensation-research module. The homepage's page description states the pitch and the price in one line: "Kit runs hiring, Outreach, vulnerability reports, and security training for teams where none of it is a full-time job ... $8/seat, 30-day trial." (That sentence sits in the served HTML's description metadata, the `meta`, `og`, `twitter` and JSON-LD `description` fields, not the rendered body, where the visible nav reads "$8/seat/mo".) This entry is about one function in one module: the AI-assisted drafting of a job posting in the Hiring module.

## The surface an agent reaches

Kit exposes Hiring to AI assistants two ways, per the [hiring agent and MCP guide](https://startupkit.app/docs/hiring-ai-agent-mcp): an in-app agent that "lives on every Hiring page", and a remote MCP server "any external client (Claude Desktop, Claude Code, Codex CLI, or your own agents) can call against your account". The MCP server is added over streamable HTTP, and the guide gives the exact line: `claude mcp add --scope user --transport http kit https://startupkit.app/api/v1/mcp`. On first use the client "walks through Kit's OAuth flow in the browser".

Three limits gate every call, and the guide is explicit that all three must clear: the connection's scopes (you grant `hiring_read` or read-and-write per module, and "Writes are off by default on the consent screen"), your own live Hiring level ("Kit re-reads your live per-module level on every single call"), and, for the write tools that matter here, Hiring admin plus an active subscription. The governing rule, repeated in both hiring docs, is that an assistant acts as the connected user: it "can never reach a job posting you can't open, and it can never do something the web UI would refuse you."

Separately, a second MCP server runs with no authentication at `https://startupkit.app/mcp`. I called it first-hand on 2026-11-23: an `initialize` returns `serverInfo` naming it `kit_docs_mcp`, version 1.0.0, and `tools/list` returns four read-only tools, `search_docs`, `get_plans`, `list_catalog_templates` and `get_catalog_template`. This is a documentation-and-catalog surface, not the hiring one: it cannot create or edit anything. It is how an assistant with no Kit account can browse the built-in hiring templates before connecting, and `list_catalog_templates` returned 20 of them (Accountant, AI / ML Engineer, Backend Engineer, and so on) when I called it.

## The drafting capability, and who does which part

What Kit documents in the [job-posting-with-AI guide](https://startupkit.app/docs/creating-a-job-posting-with-ai) is an assistant-led workflow, not a single tool that writes a posting. The page description reads: "Have Claude, or any AI assistant, draft the posting, the salary band, and the hiring stages. You publish it." One prompt describing a role drives a documented tool sequence: `hiring_get_setup_guide` (account state and what your role allows), `hiring_list_templates`, `compensation_get_salary_benchmark` ("A band from real market listings Kit indexes"), `hiring_list_credentials`, and finally `hiring_create_job_posting`.

The writing is the assistant's work, and the persistence is the tool's. The [MCP tools reference](https://startupkit.app/docs/mcp-tools-reference) shows `hiring_create_job_posting` requiring both a `title` and a `description` ("Job description in markdown (do not include title)"), already written, as input; it "Creates a new job posting in draft status. Returns the edit URL so you can review and publish it in the browser." So the brief-to-text step happens upstream in the assistant (Kit's in-app agent or an external client), and the tool records the result as a draft. The guide is candid that the draft is a first pass, not a finished posting: under "Before You Publish" it says "Read the draft. An assistant writing about your company is writing from what you gave it plus what it assumed." It does not state how much editing that read-through typically requires.

The output is a draft the human owns and publishes. The guide: "It is created in your account as a draft, with an edit URL handed back. Nothing reaches your career page until a human presses Publish." Under "What AI Cannot Do" it lists "Publish. No tool in Kit moves a posting out of draft. That is by design." That human-publication boundary is the vendor's own statement; I have not tested its enforcement.

## Why this entry claims no job, and a taxonomy note

The registry's `hr.draft-job-descriptions` asks that "a hiring manager's brief becomes a posting that needs light edits and passes the compliance review", measured by the edits a human makes before posting, the time to post, and the quality of applicants. That outcome is a conjunction, a draft that needs only light edits and one that passes a compliance review, and Kit documents the drafting step while asserting neither clause. Nothing in either hiring document says the draft is checked for bias, EEOC or protected-class wording, inclusive language, or legal compliance; there is no compliance-review tool or step. The review-like behaviour Kit does document is narrower and of a different kind: structured-data correctness for job boards ("Kit marks the listing as `TELECOMMUTE` in its structured data only when at least one is set, so without it Google Jobs never learns the role is remote"), a formatting rule ("No job title in the body"), and a deliberate refusal to screen candidates by the credentials a posting recommends ("Kit does not verify, score, rank, or filter anyone by what comes back"). None of these is a compliance review.

Because the structured coverage join reads a `jobs[]` entry as a claim on the whole outcome, and because Kit asserts no compliance-review clause, filing this as a claimant would overstate what the vendor says. So the structured cell stays empty: no registry entry, StartupKit included, carries a claim on `hr.draft-job-descriptions`, because none of the three named (below) makes the full conjunctive claim. That empty cell is the finding. Two existing entries reach it from the same direction: Ashby's profile notes its AI Content Assistant "drafts and edits recruiting copy" but found "no vendor sentence saying a hiring manager's brief becomes a posting that passes a compliance review", and Rippling's distinguishes `create_draft_hire` (the start of a hire) from drafting a description. StartupKit differs from those two in documenting the drafting half as a concrete, agent-callable tool rather than adjacent copy-editing, but it stops at the same clause they do.

The recurring pattern across all three is a taxonomy question, not a StartupKit question: the job as defined fuses two separable outcomes, generating a postable draft and reviewing it for compliance, and a product can document one without the other. Whether the taxonomy should split them is a change to the job definition itself, separately reviewable, and is noted here as a lead rather than acted on in this listing.

## Access and ownership

Reaching the drafting tool needs an account: a Kit tenant, Hiring admin, the `hiring_write` scope on the connection, and an active subscription, over OAuth, so `noAccountNeeded` is false and `auth` is `oauth`. (The no-auth `kit_docs_mcp` at `/mcp` is read-only and does not create postings, so it does not change that reading.) No `/.well-known/public-agents.json` was served at the homepage (404 on 2026-11-23), so provenance is third-party and this entry is unverified, in those words, until the domain acknowledges it.

## Pricing

Kit is paid, one per-seat subscription covering every module. I read the figure first-hand from `get_plans` on the public MCP on 2026-11-23: $8 per seat per month or $80 per seat per year, each with a 30-day trial, also priced at EUR 6.99, GBP 5.99 and PLN 29.99 per month. The plan lists "AI assistant in Kit and MCP access" among its features, so MCP access is part of the one subscription rather than a separate charge. Billing is a human card-on-file subscription; there is no agent-settled or machine-payable path, so `machinePayable` is false.

## Measures

No measured figures for the drafting workflow were found, from the vendor or a third party: Kit publishes no number for the edits a human makes to a draft before posting, the time from brief to published posting, or the resulting applicant quality. The guide's framing line, "Describing a role out loud takes a minute. Writing the posting takes an hour", is rhetorical contrast, not a measured claim, and it describes the manual baseline rather than the tool's output.
