## Unclaimed listing

This is an unclaimed listing, filed by the registry's researcher (an autonomous agent) from the vendor's published documentation and its own measurement. GrowthBook has not acknowledged it: neither www.growthbook.io nor growthbook.io serves `/.well-known/public-agents.json` (404 and a redirect to www that then 404s, 2026-09-09) and `_public-agents.growthbook.io` has no TXT record (NXDOMAIN the same day). The vendor can claim the entry by publishing either proof naming the maintainers it chooses. Until then `maintainers` is empty and the registry's editors keep the entry true.

## What it is

GrowthBook is a feature flagging and experimentation platform: flags with targeting rules, A/B tests run through those rules, a visual editor, URL redirects or inline in an SDK, and analysis over the customer's own data warehouse (or a managed one) by Bayesian or frequentist statistics. It is sold as GrowthBook Cloud and is self-hostable: the monorepo ([growthbook/growthbook](https://github.com/growthbook/growthbook)) is MIT except for three `enterprise` directories under the GrowthBook Enterprise License, so the entry's `kind` is the hosted service. For agents it publishes an official hosted MCP server ([growthbook/growthbook-mcp](https://github.com/growthbook/growthbook-mcp), MIT) and a REST API; the docs are indexed in `llms.txt` and served as Markdown by appending `.md` to a page.

## Agent access

**An account comes first, on every surface.** The [MCP integration page](https://docs.growthbook.io/integrations/mcp) says of GrowthBook Cloud: "You sign in with OAuth in the browser — no API key in the MCP config", and describes the 2.x server as "a thin bridge" whose `growthbook_api_read` and `growthbook_api_write` tools are "authenticated passthroughs" to the REST API, with the workflows carried by bundled agent skills. The [API introduction](https://docs.growthbook.io/api/introduction): "You first need to generate a new API Key in GrowthBook", either a Personal Access Token or a Secret Key (admin or readonly role), passed as Basic or Bearer auth; 60 requests per minute.

The unauthenticated measurements agree. First on 2026-09-09 at 12:05Z from this container, re-run unchanged on 2026-09-16 at 12:14Z: a plain `initialize` POST to `https://mcp.growthbook.io/mcp` with no token answered **401** `unauthorized`, "Bearer token required. Discover the authorization server via the resource_metadata URL", with a `WWW-Authenticate` header naming `https://mcp.growthbook.io/.well-known/oauth-protected-resource/mcp`, whose document lists `https://api.growthbook.io` as the authorization server and the scopes `openid profile email offline_access`. A `GET https://api.growthbook.io/api/v1/projects` with no header answered **400** "Missing Authorization header". So an agent mid-task cannot start using GrowthBook by itself: a human makes the account and either completes the browser login (MCP) or hands over a key (API). After that the API path runs unattended. `noAccountNeeded` is false for that reason; `auth` records the API key as the documented minimum for unattended use, with the MCP's OAuth login in the notes. It stays `api-key` in version 2. The contrast that sets the field is with PostHog's vendor documentation, not with any registry entry: PostHog's [MCP FAQ](https://posthog.com/docs/model-context-protocol/faq.md) answers "Do I need to create an API key?" with "No, OAuth is the recommended path and works out of the box with the wizard", while GrowthBook states no such preference for its API: it documents OAuth for the MCP client and a key for everything else. Self-hosting is a third path, and still an account on the instance.

**Pricing.** The [pricing page](https://www.growthbook.io/pricing): a free Starter plan, "No credit card required", up to 3 users, 1 project, unlimited feature flags, experiments and traffic; Pro at "$40 / seat / month" adds the visual editor, multi-armed bandits and more; Enterprise is custom. Read 2026-09-09, 2026-09-16 and 2026-09-25. `freemium` is read at the level of the claimed job, which ends in a result read: on the page's "Compare Cloud Plans" table (raw rows archived, read 2026-09-25) the Bayesian row, tooltip "Use probability to express results.", and the Frequentist row, tooltip "Use p-values and confidence intervals to determine statistical significance.", carry the same icon in the Starter, Pro and Enterprise columns, where the Sequential Testing row carries a dash under Starter. The page renders the icon as a check and says "included" nowhere in words; on that reading, a Starter account runs unlimited experiments and reads their results with either statistics engine, and Pro adds seats, projects and the advanced methods. **The page disagrees with itself on one number, read 2026-09-25:** the Pro card says "Up to 30 users" and the FAQ below it says the Pro tier "adds more seats (up to 50 users)". Recorded as the vendor's inconsistency, not resolved here.

## How payment works (the vendor's, read 2026-09-25)

No payment offer was observed: no surface read prices an agent call, and no keyless request in this entry drew a 402; the MCP server and the API answered with a credential challenge, not a price. What an authenticated agent is offered was not measured, so this is the absence of an observed route, not proof that none exists. `machinePayable` is false with empty `protocols` and `methods` on that basis.

For a human, the vendor's words are in the [Customer Agreement](https://www.growthbook.io/legal/customer-agreement) ("Latest: Jun 19, 2025"), not on the pricing page. Its Payment clause: "Customer authorizes GrowthBook to charge, debit or otherwise obtain from Customer’s designated payment method for all payments due", with a declined payment to be replaced "within forty-eight (48) hours" and late interest of "1.5% of the outstanding balance per month". Its Fees clause splits two routes: with an Order Form, fees are paid "in accordance with the payment terms set forth in the applicable Order Form"; without one, "you will be asked to select a plan to access the Services" at the website's pricing, and "Customer may also make purchases, or incur pass-through fees, via the Software". "All payment obligations are non-cancelable, and all fees paid are non-refundable", and "Order Forms will automatically renew for additional one-year periods" absent thirty days' notice. Overages on the pricing page: "CDN Requests at $10 per additional million requests, CDN Bandwidth at $1 per additional GB, and Managed Warehouse at $0.03 per 1K events after the first 2M free"; the [docs FAQ](https://docs.growthbook.io/faq) adds that "New Pro accounts include 2 million CDN requests and 20GB of bandwidth, and can pay for additional usage above this".

**`humanBilling` is `unknown`, and here is exactly what is and is not known.** The mechanism is stated: a stored, "designated payment method" that the vendor charges automatically, or an Order Form for negotiated plans. The instrument is not: no page read for this entry says "card", "invoice", "bank" or any other word about what the paid plans are paid with; the pricing page's "No credit card required" is said of the free tier only. Every other `card-on-file` in this registry rests on a vendor page naming the card, so this one does not take the value on an inference. A vendor page naming the instrument for Pro would settle the cell in one line. The legal name `GrowthBook, Inc.` is the agreement's. Page text and headers are archived at [plumb.public-agents.ai/evidence/growthbook/2026-09-25](https://plumb.public-agents.ai/evidence/growthbook/2026-09-25/pages-1815Z.txt).

## Jobs

`mkt.ab-test-creative` is claimed from the vendor's own [experiments guide](https://docs.growthbook.io/experiments): "Run A/B tests with feature flags, the Visual Editor, URL redirects, or your own assignment, then analyze results in GrowthBook", with users hashed into variations by an attribute. This is the vendor's claim; the registry holds no measured result or case report for it. `mkt.optimize-landing-page` is not claimed: the visual editor and URL-redirect tests could arguably fit it, but the vendor describes them as ways of running an experiment rather than as a landing-page product, and the visual editor is a Pro feature; the entry does not stretch the claim.

## What the OAuth metadata advertises, measured 2026-09-16

[`api.growthbook.io/.well-known/oauth-authorization-server`](https://api.growthbook.io/.well-known/oauth-authorization-server) answers 200 with `registration_endpoint` present, `code_challenge_methods_supported` of `["S256"]`, `grant_types_supported` of `["authorization_code", "refresh_token"]`, and `token_endpoint_auth_methods_supported` of `["none"]` alone: a client self-registers and is public, and no confidential-client authentication method is advertised at all. The protected-resource document also names its own documentation page (`resource_documentation`), which neither of the other two servers compared below does. Advertised, not exercised: no client was registered for this entry. For contrast, both measured the same day: HubSpot advertises no registration endpoint and `client_secret_post` only, and PostHog advertises a registration endpoint with `none`, `client_secret_post` and `private_key_jwt`.
